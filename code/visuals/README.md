# Figure sources and checks

Run `python figures.py` to regenerate the first three PDFs and their PNG previews. The default paths use `../legacy/knot_crossings_dataset.tar.gz` and `../corpus/crops/7_4.png`. These inputs can also be supplied with `--archive` and `--crop`. Run `python mixed_junctions.py` separately to regenerate `mixed-junctions.pdf` and its verification CSV. The two scripts use Matplotlib, Pillow, NumPy and SciPy.

- `switch-arcs.pdf` is an original vector drawing. The planar curve has polar radius (2+0.86\cos(3t)\) and angle (2t+\pi/2\). Height (\sin(3t)\) assigns the crossings of the usual closed two-strand, three-crossing braid. There are exactly three distinct crossing locations since equal angles require the parameters to differ by pi and the two radii coincide precisely when cos(3t) vanishes. We remove 0.062 radians on either side of the underpassing visit at each crossing. Switching the marked crossing restores that entire arc and removes the corresponding overpassing interval. Both diagrams have three visible arcs. The standard braid word reduces from three equal half-twists to one after the switch. A direct enumeration of all 27 possible three-arc Fox color assignments gives nine valid colorings for the trefoil and three after the switch. The three distinct colors in the center panel form a valid assignment. The dotted circles are annotations and carry no topological meaning. Original diagrams, suitable for reuse in the paper.
- `archive-views.pdf` displays classes from the published crossing-count corpus, which processed Philip Rideout’s source diagrams. All four are archived as six-crossing drawings. The original PNGs are given by full SHA-256 in `archive-views.csv`. The first three source slots are identical. Archive variant 0, the transformed variant 1, and a resized descendant of variant 0 are shown, followed by the representative of a different source slot at the same label. For print legibility all four receive the same contrast gain, a one-pixel foreground expansion and identical crop. The displayed transformations play no role in the numerical experiments. [Project dataset, Unlicense](https://huggingface.co/datasets/tr33hugg3r/knot-crossings) · [Philip Rideout, *Generating SVG for the Prime Knots*, 2020, CC0](https://prideout.net/blog/svg_knots/)
- `resolution-7-4.pdf` reproduces the independent Jkasd diagram of the knot (7_4\). Each view is a separate Lanczos reduction of the same native 230-pixel square followed by its own Otsu threshold. Nearest-neighbor display preserves the resulting pixels. Eight-neighbor labeling gives seven, six and one components at 230, 64 and 32 pixels. The 32-pixel component encloses five bounded white regions. The matching detailed measurements are in `../corpus/observations.csv`. [Jkasd, *Knot table*, 2008, Wikimedia Commons, public domain](https://commons.wikimedia.org/wiki/File:Knot_table.svg)
- `mixed-junctions.pdf` is original vector artwork on the same trefoil shadow. The panels restore zero, one, two and three previously omitted underpassing intervals. At a restored crossing all four adjacent half-edges meet. The program enumerates the six consecutive visits along the parameter circle. An overpass is an ordinary degree-two vertex, a gap splits its visit into two endpoints, and a filled crossing identifies its two visits into a degree-four vertex. The counts of endpoints, components and bounded regions are respectively (6,3,0), (4,1,0), (2,1,2) and (0,1,4). The independent 900-pixel raster check uses complementary 8-neighbor ink and 4-neighbor background components and recovers the same component and region counts at every stage. Original drawing and verification, suitable for use in the paper.

`python poster-transfer.py` renders `poster-transfer.pdf` from the six-resolution poster census and endpoint measurements. It reads the bundled CC0 SVG in `../legacy/` and the 528 per-diagram measurements in `../paired/poster-euler.csv`. The three example masks use the same Otsu thresholds as the census. This figure was added for the paper's external test.

The new appendix drawings are described in the [figure index](../../figures/README.md). For the photo-based panel generated by `reading-figures.py`, `python code/fetch_inputs.py paper` retrieves the exact source images from arXiv v1.
